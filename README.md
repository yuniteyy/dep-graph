# dep-graph

Инструмент визуализации графа зависимостей пакетов npm. Практическая
работа № 2 по дисциплине «Конфигурационное управление», вариант 14.

Документация дополняется по мере реализации этапов.

## Общее описание

Консольное приложение строит граф зависимостей пакета npm и визуализирует
его. Готовые средства получения зависимостей (npm, yarn, библиотеки) не
используются: данные берутся напрямую из реестра, только стандартная
библиотека Python.

## Параметры командной строки

| Параметр                | Описание                                         |
|-------------------------|--------------------------------------------------|
| `--package NAME`        | имя анализируемого пакета (обязательный)         |
| `--repo URL_OR_PATH`    | URL реестра или путь к файлу тестового репозитория (обязательный) |
| `--repo-mode remote\|test` | режим: реальный реестр по URL (по умолчанию) или тестовый файл |
| `--version X.Y.Z`       | точная версия пакета (обязательна в режиме remote) |
| `--output FILE.png`     | имя файла с изображением графа (по умолчанию `graph.png`) |
| `--max-depth N`         | максимальная глубина анализа, N ≥ 1 (по умолчанию 3) |
| `--show-config`         | вывести параметры в формате ключ-значение        |

Флаг `--show-config` выводит все параметры в формате `ключ = значение`
(на этапе 1 они выводились всегда).

### Обработка ошибок

Все параметры проверяются до начала работы. При ошибке в stderr выводится
`ошибка: …`, код возврата 2. Проверяются: пустое и недопустимое имя
пакета (для тестового режима — только заглавные латинские буквы), формат
URL (`http://`/`https://`), существование и доступность файла тестового
репозитория, допустимость режима, обязательность и формат версии,
расширение `.png` и доступность каталога для файла изображения,
корректность глубины (целое число ≥ 1), отсутствие обязательных опций.

## Сборка и тесты

Сборка не требуется (Python 3.9+, только стандартная библиотека).

```
make run ARGS="--package express --repo https://registry.npmjs.org --version 4.18.2"
make test         # или ./run.sh test, или run.bat test
make lint         # flake8 (pip install flake8 pep8-naming)
```

## Примеры использования

```
$ ./run.sh --package express --repo https://registry.npmjs.org --version 4.18.2
package   = express
repo      = https://registry.npmjs.org
repo_mode = remote
version   = 4.18.2
output    = graph.png
max_depth = 3

$ ./run.sh --package express --repo https://registry.npmjs.org --version 1.2
ошибка: версия '1.2' не соответствует формату X.Y.Z
```

Скрипт проверки всех параметров и ошибок: `scripts/stage1_config.sh`
(или `.bat`).

## Сбор данных (этап 2)

Данные берутся из HTTP API реестра npm (`GET <repo>/<имя пакета>`) только
средствами стандартной библиотеки (`urllib`, `json`). Запрашивается
сокращённый документ пакета (`application/vnd.npm.install-v1+json`),
из него берётся запись заданной версии и её поле `dependencies` —
прямые зависимости. Имена со scope (`@babel/core`) кодируются в
`@babel%2Fcore`. Документы пакетов кешируются в памяти.

```
$ ./run.sh --package chalk --repo https://registry.npmjs.org --version 2.4.2
Прямые зависимости chalk@2.4.2:
  ansi-styles: ^3.2.1
  escape-string-regexp: ^1.0.5
  supports-color: ^5.3.0
```

Ошибки (код возврата 1): пакет или версия не найдены, реестр недоступен
или вернул HTTP-ошибку, некорректный JSON. Скрипт проверки:
`scripts/stage2_direct.sh` (или `.bat`).

## Граф зависимостей (этап 3)

Граф строится обходом в ширину (BFS) без рекурсии: очередь
(`collections.deque`) и множество уже найденных узлов. Корень имеет
глубину 0, его прямые зависимости — глубину 1 и т. д. Узлы на глубине
`--max-depth` попадают в граф, но не раскрываются (в отчёте помечены
`(глубина исчерпана)`), поэтому `--max-depth 1` показывает ровно прямые
зависимости. Каждый узел раскрывается не более одного раза, так что
циклические зависимости не приводят к зацикливанию; найденные циклы
(включая самозависимость) перечисляются в конце отчёта — они ищутся
обходом в глубину, также без рекурсии.

Узлы реального реестра — это `имя@версия`. Диапазоны из `dependencies`
(`^1.2.0`, `~1.3.8`, `>=2 <4`, `1.x`, `*`, `a || b`, `npm:алиас@…`, теги
вроде `next`) разворачиваются в конкретную версию собственной
реализацией semver (`src/depgraph/semver.py`). Выбор версии повторяет
npm: предпочитаются не помеченные `deprecated`; если версия из тега
`latest` подходит под диапазон, берётся она, иначе — наибольшая
подходящая. Учитываются только `dependencies` (без `devDependencies`,
`peerDependencies`, `optionalDependencies`). Зависимости, которые нельзя
разрешить (нет пакета, нет подходящей версии, git/URL/файловые
спецификации), остаются листьями `имя@спецификация`, а в stderr
выводится `предупреждение: …`.

### Тестовый режим

`--repo-mode test --repo ФАЙЛ`: граф описывается файлом, пакеты
называются заглавными латинскими буквами:

```
# комментарий
A: B C
B: D
C: D, E
```

Каждая строка — `ПАКЕТ: зависимости через пробел или запятую`.
Пакет, который только упоминается в качестве зависимости, не имеет
собственных зависимостей. Ошибки формата (нижний регистр, нет `:`,
повторное описание пакета, неверное имя зависимости, нет корневого
пакета) сообщаются с номером строки, код возврата 1.

Примеры в `examples/repos/`: `simple.txt`, `wide.txt` (ромбы),
`chain.txt` (глубина), `cycle.txt`, `self_loop.txt`, `two_cycles.txt`
(циклы), `undefined.txt`, а также некорректные файлы в `invalid/`.

```
$ ./run.sh --repo-mode test --repo examples/repos/cycle.txt --package A --max-depth 10
Граф зависимостей A (максимальная глубина 10)
Узлов: 4, рёбер: 4
  A [0] -> B
  B [1] -> C
  C [2] -> A, D
  D [3] -> (нет)
Циклические зависимости (1):
  A -> B -> C -> A

$ ./run.sh --package chalk --repo https://registry.npmjs.org --version 2.4.2 --max-depth 2
Граф зависимостей chalk@2.4.2 (максимальная глубина 2)
Узлов: 6, рёбер: 5
  chalk@2.4.2 [0] -> ansi-styles@3.2.1, escape-string-regexp@1.0.5, supports-color@5.5.0
  ansi-styles@3.2.1 [1] -> color-convert@1.9.3
  escape-string-regexp@1.0.5 [1] -> (нет)
  supports-color@5.5.0 [1] -> has-flag@3.0.0
  color-convert@1.9.3 [2] -> (глубина исчерпана)
  has-flag@3.0.0 [2] -> (глубина исчерпана)
```

Скрипт проверки: `scripts/stage3_graph.sh` (или `.bat`).
