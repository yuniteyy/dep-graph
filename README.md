# dep-graph

Инструмент визуализации графа зависимостей пакетов npm. Практическая
работа № 2 по дисциплине «Конфигурационное управление», вариант 14.

Документация дополняется по мере реализации этапов.

## Общее описание

Консольное приложение строит граф зависимостей пакета npm и визуализирует
его. Готовые средства получения зависимостей (npm, yarn, библиотеки) не
используются: данные берутся напрямую из реестра, только стандартная
библиотека Python.

## Параметры командной строки

| Параметр                | Описание                                         |
|-------------------------|--------------------------------------------------|
| `--package NAME`        | имя анализируемого пакета (обязательный)         |
| `--repo URL_OR_PATH`    | URL реестра или путь к файлу тестового репозитория (обязательный) |
| `--repo-mode remote\|test` | режим: реальный реестр по URL (по умолчанию) или тестовый файл |
| `--version X.Y.Z`       | точная версия пакета (обязательна в режиме remote) |
| `--output FILE.png`     | имя файла с изображением графа (по умолчанию `graph.png`) |
| `--max-depth N`         | максимальная глубина анализа, N ≥ 1 (по умолчанию 3) |
| `--reverse`             | обратные зависимости: пакеты, зависящие от заданного (только `--repo-mode test`) |
| `--plantuml-jar PATH`   | локальный `plantuml.jar` для отрисовки (по умолчанию переменная `PLANTUML_JAR`) |
| `--plantuml-server URL` | PlantUML-сервер, если jar не задан (по умолчанию `https://www.plantuml.com/plantuml`) |
| `--print-puml`          | вывести исходный текст PlantUML на экран         |
| `--show-config`         | вывести параметры в формате ключ-значение        |

Флаг `--show-config` выводит все параметры в формате `ключ = значение`
(на этапе 1 они выводились всегда).

### Обработка ошибок

Все параметры проверяются до начала работы. При ошибке в stderr выводится
`ошибка: …`, код возврата 2. Проверяются: пустое и недопустимое имя
пакета (для тестового режима — только заглавные латинские буквы), формат
URL (`http://`/`https://`), существование и доступность файла тестового
репозитория, допустимость режима, обязательность и формат версии,
расширение `.png` и доступность каталога для файла изображения,
корректность глубины (целое число ≥ 1), отсутствие обязательных опций.

## Сборка и тесты

Сборка не требуется (Python 3.9+, только стандартная библиотека).

```
make run ARGS="--package express --repo https://registry.npmjs.org --version 4.18.2"
make test         # или ./run.sh test, или run.bat test
make lint         # flake8 (pip install flake8 pep8-naming)
make demo         # все проверочные скрипты scripts/*.sh (нужны сеть, Java)
```

## Примеры использования

```
$ ./run.sh --package express --repo https://registry.npmjs.org --version 4.18.2
package   = express
repo      = https://registry.npmjs.org
repo_mode = remote
version   = 4.18.2
output    = graph.png
max_depth = 3

$ ./run.sh --package express --repo https://registry.npmjs.org --version 1.2
ошибка: версия '1.2' не соответствует формату X.Y.Z
```

Скрипт проверки всех параметров и ошибок: `scripts/stage1_config.sh`
(или `.bat`).

## Сбор данных (этап 2)

Данные берутся из HTTP API реестра npm (`GET <repo>/<имя пакета>`) только
средствами стандартной библиотеки (`urllib`, `json`). Запрашивается
сокращённый документ пакета (`application/vnd.npm.install-v1+json`),
из него берётся запись заданной версии и её поле `dependencies` —
прямые зависимости. Имена со scope (`@babel/core`) кодируются в
`@babel%2Fcore`. Документы пакетов кешируются в памяти.

```
$ ./run.sh --package chalk --repo https://registry.npmjs.org --version 2.4.2
Прямые зависимости chalk@2.4.2:
  ansi-styles: ^3.2.1
  escape-string-regexp: ^1.0.5
  supports-color: ^5.3.0
```

Ошибки (код возврата 1): пакет или версия не найдены, реестр недоступен
или вернул HTTP-ошибку, некорректный JSON. Скрипт проверки:
`scripts/stage2_direct.sh` (или `.bat`).

## Граф зависимостей (этап 3)

Граф строится обходом в ширину (BFS) без рекурсии: очередь
(`collections.deque`) и множество уже найденных узлов. Корень имеет
глубину 0, его прямые зависимости — глубину 1 и т. д. Узлы на глубине
`--max-depth` попадают в граф, но не раскрываются (в отчёте помечены
`(глубина исчерпана)`), поэтому `--max-depth 1` показывает ровно прямые
зависимости. Каждый узел раскрывается не более одного раза, так что
циклические зависимости не приводят к зацикливанию; найденные циклы
(включая самозависимость) перечисляются в конце отчёта — они ищутся
обходом в глубину, также без рекурсии.

Узлы реального реестра — это `имя@версия`. Диапазоны из `dependencies`
(`^1.2.0`, `~1.3.8`, `>=2 <4`, `1.x`, `*`, `a || b`, `npm:алиас@…`, теги
вроде `next`) разворачиваются в конкретную версию собственной
реализацией semver (`src/depgraph/semver.py`). Выбор версии повторяет
npm: предпочитаются не помеченные `deprecated`; если версия из тега
`latest` подходит под диапазон, берётся она, иначе — наибольшая
подходящая. Учитываются только `dependencies` (без `devDependencies`,
`peerDependencies`, `optionalDependencies`). Зависимости, которые нельзя
разрешить (нет пакета, нет подходящей версии, git/URL/файловые
спецификации), остаются листьями `имя@спецификация`, а в stderr
выводится `предупреждение: …`.

### Тестовый режим

`--repo-mode test --repo ФАЙЛ`: граф описывается файлом, пакеты
называются заглавными латинскими буквами:

```
# комментарий
A: B C
B: D
C: D, E
```

Каждая строка — `ПАКЕТ: зависимости через пробел или запятую`.
Пакет, который только упоминается в качестве зависимости, не имеет
собственных зависимостей. Ошибки формата (нижний регистр, нет `:`,
повторное описание пакета, неверное имя зависимости, нет корневого
пакета) сообщаются с номером строки, код возврата 1.

Примеры в `examples/repos/`: `simple.txt`, `wide.txt` (ромбы),
`chain.txt` (глубина), `cycle.txt`, `self_loop.txt`, `two_cycles.txt`
(циклы), `undefined.txt`, а также некорректные файлы в `invalid/`.

```
$ ./run.sh --repo-mode test --repo examples/repos/cycle.txt --package A --max-depth 10
Граф зависимостей A (максимальная глубина 10)
Узлов: 4, рёбер: 4
  A [0] -> B
  B [1] -> C
  C [2] -> A, D
  D [3] -> (нет)
Циклические зависимости (1):
  A -> B -> C -> A

$ ./run.sh --package chalk --repo https://registry.npmjs.org --version 2.4.2 --max-depth 2
Граф зависимостей chalk@2.4.2 (максимальная глубина 2)
Узлов: 6, рёбер: 5
  chalk@2.4.2 [0] -> ansi-styles@3.2.1, escape-string-regexp@1.0.5, supports-color@5.5.0
  ansi-styles@3.2.1 [1] -> color-convert@1.9.3
  escape-string-regexp@1.0.5 [1] -> (нет)
  supports-color@5.5.0 [1] -> has-flag@3.0.0
  color-convert@1.9.3 [2] -> (глубина исчерпана)
  has-flag@3.0.0 [2] -> (глубина исчерпана)
```

Скрипт проверки: `scripts/stage3_graph.sh` (или `.bat`).

## Обратные зависимости (этап 4)

`--reverse` выводит пакеты, которые зависят от заданного (прямо или
транзитивно). Используется тот же BFS, что и на этапе 3: репозиторий
«переворачивается» (рёбра меняют направление), и обход запускается от
заданного пакета; глубина и циклы обрабатываются так же. Отчёт использует
стрелку `<-` («зависит от»). Режим доступен только для тестового
репозитория: реестр npm не предоставляет списка всех пакетов, зависящих
от данного, поэтому для `--repo-mode remote` выдаётся ошибка (код 2).

```
$ ./run.sh --repo-mode test --repo examples/repos/simple.txt --package D --reverse
Обратные зависимости D (максимальная глубина 3)
Узлов: 4, рёбер: 4
  D [0] <- B, C
  B [1] <- A
  C [1] <- A
  A [2] <- (нет)
```

Скрипт проверки (дерево, ромбы, глубина, циклы, ошибки):
`scripts/stage4_reverse.sh` (или `.bat`).

## Визуализация (этап 5)

Граф переводится в текст на языке PlantUML и сохраняется рядом с
изображением (`--output graph.png` даёт `graph.puml` и `graph.png`).
Корень выделен голубым, узлы, не раскрытые из-за глубины, нарисованы
пунктиром, рёбра циклов — красные. В режиме `--reverse` стрелки рисуются
от зависимого пакета к тому, от которого он зависит.

```
@startuml
title Граф зависимостей react-dom@18.2.0 (глубина не более 20)
skinparam shadowing false
rectangle "react-dom@18.2.0" as n0 #LightSkyBlue
rectangle "loose-envify@1.4.0" as n1
rectangle "scheduler@0.23.2" as n2
rectangle "js-tokens@4.0.0" as n3
n0 --> n1
n0 --> n2
n1 --> n3
n2 --> n1
@enduml
```

PNG строится одним из двух способов:

* **локально** — `--plantuml-jar PATH` (или переменная `PLANTUML_JAR`);
  нужны Java и Graphviz (`dot`), `plantuml.jar` скачивается с
  <https://plantuml.com/download>. Файл jar — бинарный, в репозиторий не
  входит (он в `.gitignore`, как и `*.png`);
* **через сервер** — без jar текст кодируется (deflate + алфавит PlantUML,
  стандартная библиотека `zlib`) и отправляется на `--plantuml-server`.
  Для очень больших графов URL получается слишком длинным — тогда нужен jar.

Ошибки: нет файла jar (код 2), нет Java, ошибка PlantUML, сервер
недоступен или вернул не PNG, файл нельзя записать (код 1).

```
$ export PLANTUML_JAR=~/tools/plantuml.jar
$ ./run.sh --package express --repo https://registry.npmjs.org --version 4.18.2 --max-depth 20 --output out/express.png
...
Исходник PlantUML: out/express.puml
Изображение графа: out/express.png
```

Скрипты: `scripts/stage5_visualize.sh` — три реальных пакета, глубина,
ромбы, цикл, обратные зависимости, ошибки; `scripts/stage5_compare.sh` —
сравнение с npm. Сгенерированные изображения (`out/*.png`) в репозиторий
не коммитятся.

### Сравнение со штатным инструментом npm

Штатный инструмент визуализации зависимостей npm — `npm ls --all`.
Сравнение выполняет `scripts/compare_with_npm.py NAME@VERSION`: в
пустом проекте выполняется `npm install --package-lock-only`
(без загрузки пакетов), затем `npm ls --all --json`; множество узлов
`имя@версия` сравнивается с графом depgraph при неограниченной глубине.
npm используется только как эталон для сравнения, сам depgraph его не
вызывает.

| Пакет            | depgraph | npm ls | Результат                                    |
|------------------|---------:|-------:|----------------------------------------------|
| express@4.18.2   | 67       | 67     | совпадает полностью                          |
| chokidar@3.5.3   | 14       | 14     | совпадает полностью                          |
| mocha@10.2.0     | 78       | 77     | лишний `yargs-parser@20.2.9` у depgraph      |
| react-dom@18.2.0 | 3        | 4      | у npm есть `react@18.3.1`                    |
| jest@29.5.0      | 265      | 268    | у npm три узла `…@None` (необязательные peer)|

Причины расхождений:

1. **Дедупликация npm (mocha).** `mocha` зависит от `yargs-parser@20.2.4`,
   а `yargs@16.2.0` — от `yargs-parser@^20.2.2`. npm размещает в дереве
   одну копию `20.2.4`, удовлетворяющую обоим диапазонам (в `npm ls`
   вторая отмечена `deduped`). depgraph разрешает каждое ребро независимо
   и для `^20.2.2` берёт наибольшую подходящую версию `20.2.9`, поэтому
   узлов на один больше. Рёбра при этом те же: различается лишь выбор
   версии для общей зависимости.
2. **Peer-зависимости (react-dom).** С npm 7 `peerDependencies` ставятся
   автоматически, поэтому `npm ls` показывает `react@18.3.1`. depgraph по
   заданию анализирует только `dependencies` и peer-зависимости не
   учитывает.
3. **Необязательные peer-зависимости (jest).** Для `node-notifier`,
   `ts-node`, `babel-plugin-macros` (помечены `optional` в
   `peerDependenciesMeta`) `npm ls` показывает пустые узлы без версии
   (`@None` в нашем отчёте). Реальных пакетов за ними нет.
4. **Прочее.** depgraph не учитывает `devDependencies`, `optionalDependencies`
   (npm их показывает, если они установлены на текущей платформе),
   `overrides` и `engines`. Выбор версии зависит от содержимого реестра на
   момент запуска, поэтому на разных датах результат может отличаться.
   npm рисует дерево (повторяющиеся поддеревья), depgraph — граф, где
   каждый `имя@версия` присутствует один раз.

Для пакетов без peer-зависимостей и общих поддеревьев с разными
диапазонами (express, chokidar, eslint, webpack, @babel/core) графы
совпадают узел в узел.

## Структура репозитория

```
src/depgraph/     исходный код: cli, registry, semver, repository, testrepo,
                  graph, report, plantuml, app
tests/            модульные тесты (unittest), поддельный реестр fake_registry
examples/repos/   тестовые репозитории и invalid/ с некорректными файлами
scripts/          скрипты реальной ОС (.sh и .bat) для проверки этапов,
                  compare_with_npm.py — сравнение с npm
Makefile, run.sh, run.bat   запуск, тесты, линтер
```

Тесты не требуют сети: реестр заменяется поддельным, а HTTP-слой
проверяется на локальном сервере. Тест настоящего рендера PlantUML
выполняется, если задан `PLANTUML_JAR` и установлена Java.

## Качество кода

Настройки `flake8` в `.flake8`: строки до 80 символов, цикломатическая
сложность не более 10. Функции короче 40 строк, не более 7 аргументов,
документация оформлена docstring, магические числа вынесены в
именованные константы, имена соответствуют PEP 8 (`pep8-naming`).
